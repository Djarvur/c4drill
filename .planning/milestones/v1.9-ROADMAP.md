## Phase 4: C3 Boundary Node Fix

**Goal:** Fix `addResolvedBoundaryNode` so C3 views resolve cross-container links to the sibling container, not the parent system. Add a regression test.

**Requirements:** BOUND-01, BOUND-02, BOUND-03

**Success criteria:**
1. C3 diagram for `mainSystem.localIDP` shows `RBAC` (sibling container) as boundary node, not `Main System` (parent)
2. C1 and C2 boundary resolution unchanged (existing boundary tests pass)
3. New regression test covers the C3 cross-container sibling case

**Context:**
- Bug diagnosed in DEFERRED-04 (`.planning/milestones/v1.8-phases/03-compatibility-validation/deferred-items.md`)
- Fix is in `internal/view/scope.go` (`addResolvedBoundaryNode`, line 625)
- The function needs to know the container scope (the C3 view's expanded container path) and stop walking up before crossing above the container's parent

**Key decisions:**
- D-01: The walk-up should stop when the peer path reaches the same parent level as the expanded container. A peer like `mainSystem.rbac` shares parent `mainSystem` with `mainSystem.localIDP`, so `rbac` is the boundary — not `mainSystem`.

## Post-Archive Follow-Up Fixes (2026-08-06)

After v1.9 was archived, deeper testing revealed the initial fix was incomplete:

### Fix 1: Path-prefix divergence algorithm (commit 990da42)
The v1.9 `expandedParent` guard only caught direct siblings under the same parent. Peers from a different subtree (e.g., `mainSystem.sshAuth.*` in a view of `mainSystem.storages.*`) walked past the divergence to `mainSystem`. Replaced with a path-prefix divergence algorithm: find the common prefix between peer and `v.ExpandedUnit`, boundary = peer's ancestor one level below the divergence.

### Fix 2: IsBoundary field (commit 2463951)
Setting `IsExternal=true` on all boundary nodes fixed placement (top-level, outside cluster) but broke styling — regular containers rendered gray (`getExternalStyle`) instead of their normal blue. Added `Entry.IsBoundary` as the view-scope signal for placement, keeping `IsExternal` as the unit-type signal for styling. Graph builder checks `IsBoundary || IsExternal`.

### Known limitation: cluster box encompasses boundary nodes (commit 6e08f25)
go-graphviz's WASM cgraph calls `agsubnode` on edge creation between root-level and cluster-internal nodes, reassigning root nodes to the cluster subgraph. This causes GraphViz to draw the cluster bounding box around boundary nodes. `compound=true` does not prevent it. Functional behavior (edges render, node structure correct) is verified; only the visual box is wrong. Deferred — cosmetic.
