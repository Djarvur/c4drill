<objective>
Fix DEFERRED-04: `addResolvedBoundaryNode` in `internal/view/scope.go` walks past the sibling level when resolving cross-container links in C3 views, creating a boundary node for the parent system instead of the sibling container.

Purpose: C3 diagrams (e.g., `mainSystem.localIDP`) currently show `Main System [+]` (the parent being viewed) as a boundary node when a component links to a sibling container (e.g., `mainSystem.rbac`). The parent is the expanded container's own ancestor — surfacing it as an external boundary node is confusing and wrong. The sibling container is the correct boundary.

Output: A bounded `addResolvedBoundaryNode` (D-01), a C3 regression test (BOUND-03), and a full-suite + multilevel-fixture verification confirming C1/C2 are unchanged (BOUND-02).
</objective>

```go
// addResolvedBoundaryNode resolves a link peer to its nearest visible ancestor
// in the view and adds it as a boundary node if it's outside the view's scope.
func addResolvedBoundaryNode(v *View, m *parser.Model, peer, scopePath string) {
    if _, exists := v.Units[peer]; exists { return }
    for {
        idx := strings.LastIndex(peer, ".")
        if idx <= 0 { break }
        peer = peer[:idx]
        if _, exists := v.Units[peer]; exists { return } // internal nested reference
    }
    if _, exists := v.Units[peer]; !exists {
        v.Units[peer] = createExternalBoundaryNode(m, peer, scopePath)
        v.UnitOrder = append(v.UnitOrder, peer)
    }
}
```

Bug trace (verified) — peer `mainSystem.rbac`, scope `mainSystem.localIDP`, C3 view holds only `mainSystem.localIDP.*` entries:
1. `v.Units["mainSystem.rbac"]` miss → enter loop
2. strip → `peer = "mainSystem"`; `v.Units["mainSystem"]` miss (parent not in C3 view) → continue
3. `LastIndex("mainSystem", ".") == -1` → break
4. create boundary node for `mainSystem` (WRONG — should be `mainSystem.rbac`)

D-01 fix trace — compute `scopeParent` from `scopePath` (`mainSystem.localIDP` → `mainSystem`); BEFORE each strip, if the would-be-stripped value equals `scopeParent`, break and keep the current peer as the boundary:
- peer `mainSystem.rbac`, scopeParent `mainSystem` → would-strip-to `mainSystem` == scopeParent → BREAK → boundary `mainSystem.rbac` (FIXED)
- peer `externalSys`, scopeParent `mainSystem` → `LastIndex` -1 → break → boundary `externalSys` (UNCHANGED)
- peer `mainSystem.localIDP.grpcAPIs.authAPI`, scopeParent `mainSystem` → strips to `...grpcAPIs` (≠parent), then `mainSystem.localIDP` which IS in view → return internal (UNCHANGED)

Why C1/C2 are untouched (BOUND-02):
- C1 never calls `addResolvedBoundaryNode` (it routes through `resolveAndAddBoundary` → `resolveToTopLevel`/`resolveToViewAncestor`).
- C2 calls it with `scopePath = systemPath` (a top-level name, e.g. `mainSystem` — no dot → `scopeParent = ""`). The bound `stripped == ""` is never true, so the walk is identical to today.
