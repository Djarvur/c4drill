<objective>
CTX-03: make `buildCluster` recursive so expanded units render depicted nested elements through their intermediate containers (nested clusters, not flat lists), so the nesting picture on a non-expanded scheme matches the drill-down views.

Purpose: today `buildCluster` (internal/graph/builder.go L610-658) computes `IsExpanded`/`HasSubunits` for each child and then IGNORES both, appending every child as a flat node — a nested container inside an expanded cluster renders as a flat collapsed box and grandchildren never appear. The recursion already exists one function over (`buildNestedCluster`, L212-272); this plan copies its child-dispatch into `buildCluster`.

Output: Recursive `buildCluster`, a new structure test in builder_test.go (RED first), and the D-07 expanded-but-empty guard + 🔍 affordance preserved.

Known golden impact (BY DESIGN): this change alters output for any model with expanded clusters containing subunit-containers. The committed cmd goldens (`cmd/c4drill/testdata/multilevel.expanded.dot` and friends) will fail their baseline tests after GREEN. Those failures are the documented CTX-03 delta and are re-baselined in ONE consolidated task in plan 37-05 (RESEARCH Pitfall 1) — do NOT re-baseline goldens in this plan.
</objective>
