func BuildIndex(units map[string]*model.Unit, parentPath string) map[string]*UnitInfo {
    index := make(map[string]*UnitInfo)
    for name, unit := range units {
        fullPath := name
        if parentPath != "" {
            fullPath = parentPath + "." + name
        }
        index[fullPath] = &UnitInfo{Unit: unit, FullPath: fullPath, Parent: parentPath}
        if len(unit.Subunits) > 0 {
            subIndex := BuildIndex(unit.Subunits, fullPath)
            maps.Copy(index, subIndex)
        }
    }
    return index
}

  <behavior>
    The resolver rewrites `Link.Peer` strings in place across every Unit.Links and Unit.LinksFrom in the model (top-level units + all subunits). Cases:

    - Dotted peer (`strings.Contains(peer, ".")`) → return peer unchanged. (D-16 step 1)
    - Bare peer on a top-level host (e.g. host path `actorA`, peer `messageBus`) → search the root scope `m.Units`; if `m.Units["messageBus"]` exists, rewrite to `messageBus`; else error. (D-15 root step)
    - Bare peer on a nested host (e.g. host path `a.b.c`, peer `x`) → walk-up nearest-first: search `a.b`'s children, then `a`'s children, then root `m.Units`; first scope with the key wins; rewrite to `<scope>.x`; else error. (D-13/D-14/D-15)
    - Nearest-first precedence: if `x` exists at multiple ancestor scopes (e.g. `a.b.x` AND `a.x`), the nearer scope (`a.b.x`) wins silently — NO error. (D-14)
    - Unresolvable bare peer (no ancestor scope has the key) → return `*ResolveError` naming the peer and the host unit. (D-16 step 2 miss-at-root)
    - Same-depth multi-match → author the defensive error branch, but it is structurally unreachable (`Subunits map[string]*Unit` has unique keys per parent — RESEARCH.md Pitfall 3). Do NOT construct a test for it.

    **HS-2 (forward-compat contract, no dedicated task):** Relative peers authored inside templates resolve at the instantiation-site parent (Phase 31 D-01/D-02). Phase 30 ships BEFORE template.Expand exists, so this is satisfied BY CONSTRUCTION: the resolver treats every unit uniformly (the tree-walk in resolveUnits visits all units including any future templated ones, and reads each unit's structural parent path). No template-special-case logic. No dedicated HS-2 test is possible in Phase 30 (templates don't exist yet); the corpus test + uniform walk together guarantee HS-2 holds once Phase 31 lands and inserts template.Expand BEFORE this pass in the pipeline.

    Acceptance (ERGO-02): the existing corpus (valid.toml, expanded.toml, multilevel.toml) has a byte-identical `(unitPath, link.Peer)` set before and after Resolve. Note the corpus has 3 bare peers (`user`, `external`, `externalSys`), each resolving to a top-level unit → identity rewrite → set unchanged.

    Cases (input host path + peer → expected rewritten peer or error):

    Package `internal/peer` with:
    - Exported `func Resolve(m *parser.Model) error` — entry point; nil-safe (`if m == nil { return nil }`); delegates to unexported `resolveUnits(m.Units, "", m)`.
    - Unexported `func resolveUnits(units map[string]*model.Unit, parentPath string, m *parser.Model) error` — mirrors `validator.BuildIndex` recursion (internal/validator/index.go:24-43); at each unit, calls `resolveUnitLinks` then recurses into `unit.Subunits` with `fullPath`.

    - Unexported `func resolvePeer(hostPath, peer string, m *parser.Model) (string, error)` — D-16 gate: if `strings.Contains(peer, ".")` return peer unchanged; else walk-up via `ancestorScopes(hostPath, m)`.
    - Unexported `func ancestorScopes(hostPath string, m *parser.Model) []map[string]*model.Unit` — returns ancestor children-maps nearest-first. For `hostPath="a.b.c"`: `[\parent of a.b.c's children-map, parent of a.b's children-map, m.Units]` = `[a.b.Subunits, a.Subunits, m.Units]`. Construct by splitting hostPath on "." and walking DOWN from root: start at `m.Units`, descend to the host's parent, collecting each level's Subunits. For top-level host (`hostPath="x"`), returns just `[m.Units]`.
    - Type `type ResolveError struct { Peer, Host string }` with `func (e *ResolveError) Error() string` returning e.g. `cannot resolve peer "x" from unit "a.b.c"`. (Mirrors `*parser.ParseError` struct-with-Error idiom — read internal/parser/errors.go for the shape.)

    Stdlib only: `errors`, `strings`. No new external dependency.

    Error policy: fail-fast (return first `*ResolveError`). Rationale per RESEARCH.md Open Question 2: a model with one unresolvable peer usually has a typo; one clear error beats a wall.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| TOML author input → parsed Model | Untrusted author-controlled TOML is decoded by `parser.Parse` (Phase 30 does not touch this boundary — it consumes the already-parsed Model) |
| Parsed Model → peer.Resolve | Resolve reads the Model's unit tree and rewrites Link.Peer strings. The rewritten strings are constructed from existing map keys + the peer string; no eval/shell/network/filesystem access. |
| peer.Resolve → validator.Validate | The validator's BuildIndex/ValidateReferences consume the rewritten (absolute-only) peers. No new trust boundary — Resolve produces the same shape the validator already expects. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-01 | Tampering | resolvePeer path construction | accept | Rewritten peers are built from `parentPath + "." + mapKey` where mapKey is a TOML-decoded unit name. No path traversal possible — the output is consumed only by `BuildIndex` (map lookup). A crafted peer like `peer = "../../etc/passwd"` contains "." → D-16 step 1 treats it as absolute → left untouched → validator reports "undefined unit". No filesystem access anywhere in the pass. |
| T-30-02 | Denial of Service | ancestorScopes walk depth | accept | Walk depth is bounded by model nesting (typically < 6 levels). A pathologically deep model would hit Go stack limits in parser.Parse before Resolve runs. Acceptable for a local CLI tool processing trusted author input. No mitigation needed. |
| T-30-03 | Information Disclosure | ResolveError messages | accept | Error names the peer and host unit (author-facing diagnostic data, not secrets). Matches existing parser/validator error-verbosity conventions. No PII or secrets in TOML models. |
| T-30-04 | Tampering | in-place mutation of LinksFrom before validator.populateIncomingLinks | accept | Resolve runs BEFORE validator.Validate, so LinksFrom contains only authored entries at resolve time (mirrors are added later by populateIncomingLinks at internal/validator/index.go:70-81). Iterating and rewriting authored LinksFrom is safe. No aliasing risk (unlike templates' HS-1) because Resolve runs once on a freshly-parsed, unaliased model. |

**Summary:** No high-severity threats. All dispositions are ACCEPT (low-value local CLI target, pure string transform, no I/O). No ASVS L1 controls required beyond what the existing parser/validator already enforce.
