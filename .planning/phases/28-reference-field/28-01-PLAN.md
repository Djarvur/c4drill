## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| TOML model file → parser | User-authored content (the `reference` URL string) crosses here. Untrusted by default — the model file is local but may be shared/downloaded. |
| Parser → graph → render → SVG/HTML output | The URL string flows from model through to the rendered diagram's `URL` attribute and into the HTML JS shim's click handler. |
| Rendered SVG/HTML → reader's browser | The 📖 click navigates the reader's browser to the URL. Crosses the trust boundary into the reader's context (new tab for external, same-tab for internal). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-01 | Tampering | User-authored `reference` URL injected into SVG `<a href>` / GraphViz `URL` attribute | mitigate | The URL is already HTML-escaped by GraphViz's HTML-label pipeline (the existing `html.EscapeString` path at converter.go:215 for titles, and GraphViz's own attribute escaping for `URL=`). Verify no raw `<`/`"`/`&` survive into the SVG; the renderer MUST NOT bypass escaping. No new escaping code needed — confirmed by reading converter.go:175-225. |
| T-28-02 | Information Disclosure | `javascript:` / `data:` URI schemes in `reference` could execute in the reader's browser when the 📖 is clicked (XSS via URL attribute) | mitigate | The HTML JS shim (Task 2) MUST only honor `http://`, `https://`, and `//` (protocol-relative) prefixes for `window.open`. Any other scheme (javascript:, data:, vbscript:) falls through to the default `window.location.href=h` path — which for `javascript:` WOULD execute. STRENGTHEN the shim: if the href does NOT start with http(s):// or // or a relative path (.html/.svg), do NOT navigate at all (no-op the click). This is a single additional `else` branch in the `go` function. Document this as the REF-04 distinct-routing contract. |
| T-28-03 | Spoofing | A `reference` URL that visually mimics an internal drill-down link (e.g., a same-origin-looking path) could trick the reader | accept | The 📖 glyph is the visible affordance that the link is EXTERNAL. Internal drill-down has no 📖. Readers are trained by the 🔍 precedent to read glyphs as link-type indicators. Low risk; mitigated by the glyph convention. |
| T-28-04 | Repudiation | N/A — local tool, no audit log relevant | accept | C4Drill is a single-shot CLI producing static diagrams; there is no transaction log to repudiate. |
| T-28-05 | DoS | Extremely long `reference` URL blows up SVG label width | accept | GraphViz truncates over-long attributes and the URL is in the `URL=` attribute (not the visible label — only "📖" is visible). No length-related DoS vector. |
| T-28-SC | Tampering | go module installs (none in this phase) | accept | Phase 28 adds NO new dependencies — `go.mod`/`go.sum` unchanged. No npm/pip/cargo either. Verified by reading: only stdlib (`slices`) + existing project deps are used. |

## Mitigation Strengthening Note (T-28-02)

The Task 2 shim description above specifies branching on http(s):// and //. The threat model adds a hardening requirement: the `else` branch must NOT blindly call `window.location.href=h` for arbitrary schemes. Update the shim so the final `else` only fires for hrefs that look like relative internal navigation (start with `.` or `/` or contain no scheme). For any href that has a scheme other than http(s) (e.g. `javascript:`), the click handler MUST no-op (`e.preventDefault()` with no navigation). Carry this requirement into Task 2's shim implementation.
