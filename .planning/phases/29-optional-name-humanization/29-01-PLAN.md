<objective>
Implement optional display-name humanization: when a unit omits its TOML `name` field, derive a readable display name from the last segment of the unit's identifier via a dumb camelCase split (no acronym preservation). Explicit `name =` always wins. This is a pure pre-processing concern landing at parse time; validator/view/render stay untouched.

Purpose: Removes pure boilerplate (`name = "Session Manager"` adds nothing the identifier `sessionManager` doesn't) without breaking any existing model. ERGO-03 (optional name), ERGO-04 (dumb split, no acronyms), ERGO-05 (explicit wins). The humanize function is also the stable artifact Phase 31 (XC-04) will reuse when it relocates the call to a post-template-expansion pass.

Output: `internal/model/humanize.go` (the function), `internal/model/humanize_test.go` (the algorithm contract), a one-line parse-time hook in `internal/parser/parser.go`, and extended tests in `internal/parser/parser_test.go` covering ERGO-03/05 and a backward-compat regression assertion.
</objective>

<feature>
  <name>Identifier humanization + parse-time Unit.Name fallback</name>
  <files>internal/model/humanize.go, internal/model/humanize_test.go, internal/parser/parser.go, internal/parser/parser_test.go</files>
  <behavior>
    model.Humanize converts a TOML identifier segment (camelCase or PascalCase) into a space-separated, Title-cased display name with NO acronym preservation. Exact contract (the 9-row D-01 reference table — ALL rows must pass):

    | input segment | Humanize output |
    |---|---|
    | "linuxSystem"   | "Linux System" |
    | "localIDP"      | "Local IDP"    |
    | "sessionManager"| "Session Manager" |
    | "sessionAPI"    | "Session API"  |
    | "gRPC"          | "Grpc"         |
    | "grpcAPIs"      | "Grpc Apis"    |
    | "webapp"        | "Webapp"       |
    | "IDPToken"      | "Idp Token"    |
    | ""              | ""             |

    Integration (parser): after parsing a Unit in parseUnitWithOrder, if unit.Name == "" then unit.Name = model.Humanize(name) where `name` is the function parameter (already the last path segment). This MUST cover both top-level units and nested subunits (both flow through parseUnitWithOrder). An explicit non-empty `name =` is NEVER overwritten.

    Backward-compat: every existing fixture (testdata/*.toml, skill/examples/*.toml already carrying explicit name=) parses to byte-identical Unit.Name values.
  </behavior>
  <implementation>
    Hand-rolled rune scan using stdlib `unicode` (IsUpper/IsLower) and `strings` (ToLower, Join, ToUpper). NO regexp. NO new dependencies. NO acronym allowlist. ~25-30 LOC.

    Boundary heuristic (starting hypothesis from RESEARCH.md Pattern 2 — iterate until the 9-row table passes):
    1. Split on lower→upper transition (linuxSystem→linux|System, localIDP→local|IDP, sessionAPI→session|API).
    2. Split on upper→upper→lower transition so the last upper of a run starts the next word (IDPToken→IDP|Token).
    3. A leading lowercase letter followed by an upper-run is treated as ONE word so gRPC→"Grpc" (not "G Rpc") and grpcAPIs→"Grpc Apis".
    Then Title-case each word: lowercase the whole word, capitalize the first rune. Join with single space.

    THE TABLE IS THE CONTRACT. If the heuristic above does not produce all 9 rows exactly, adjust the heuristic — do NOT relax the table. Add any additional edge-case rows discovered during implementation to the test (e.g. already-title-case input, single-char input, all-uppercase input) but do not remove or alter the 9 mandatory rows.

    Parser hook (one line, in parseUnitWithOrder right after `unit.Type = inferGenericType(...)` at parser.go:193):

    Add a 2-line comment above it citing ERGO-03/05 and noting Phase 31's XC-04 will relocate this to a post-expansion pass.
  </implementation>
