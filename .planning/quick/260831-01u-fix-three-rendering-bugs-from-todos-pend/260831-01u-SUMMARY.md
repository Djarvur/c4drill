## Bug 1 — Bisect Verdict (corrects the todo's attribution)

The todo attributed the root bloat to b2447da (phase 38, v1.22.0). **The bisection corrects this: the culprit is phase 37 (v1.21.0), commits introducing CTX-02 (deep-link chains) and CTX-03 (recursive buildCluster).**

Empirical evidence (deepcross fixture, root DOT, node statements):

| Binary | Root nodes | Clusters | Verdict |
| ------ | ---------- | -------- | ------- |
| v1.20.3 | 3 (top-level only) | 2 | compact C1 |
| v1.21.0 | 8 (entire model) | 3 | flooded |
| HEAD (pre-fix) | 8 (entire model) | 3 | flooded |

Supporting static evidence: the v1.21.0..v1.22.0 builder diff for C1 paths is flag-threading + label-guard only (`git diff v1.21.0..v1.22.0 -- internal/graph/builder.go` — buildC1ViewGraph hunk changes `v.Plain` → `renderOptsFromView(v)`), and scope.go is untouched in that window. v1.20.3 has no `UnfoldChain` and a flat (one-level) buildCluster. The reporter's "pre-v1.22.0" binary was evidently pre-v1.21.0.

The flood mechanism (three stacked causes, all fixed):
1. **buildC1ViewGraph unfolded whole subtrees** for `IsExpanded || UnfoldChain` entries via buildCluster's CTX-03 recursion. Fix: `buildVisibleCluster` renders exclusively the view's visible paths (author-expanded direct subunits + CTX-02 chain entries); a visible child without visible descendants renders as a collapsed node (🔍 preserved via buildNode). Hand-built views without VisiblePaths keep the recursive fallback. C2/C3 boundary views and `--expanded` are untouched.
2. **Chain insertion fired for internal links** — every nested link (even inside one system) chained its target into the root, converging the root on the whole model ("removing expanded changes nothing" in the todo). Fix (scope.go): guard (a) skips links whose source resolves INSIDE the peer's depicted subtree (internal detail); guard (b) fires `ensureDeepLinkChain` only for genuine deep links — source outside the peer's **top-level system**; within-system cross-container links resolve at the visible-container level with targets staying collapsed. Cross-system links keep the CTX-02 true-target contract.
3. **Validator mirrors drove boundary resolution** — a cross-system mirror (e.g. api's `linkFrom {peer: actors.audit.archive, Mirror}`) re-revealed the source-side subtree. Fix: `resolveBoundaryLink` skips Mirror links (WR-02 — mirrors are duplicates of links already scanned from their own unit; countIncomingPairs already excluded them).

CTX-02 contract preserved: edges reach the TRUE target; TestGenerateC1View_DeepLinkTargetKeepsContainerChain, TestBuildGraph_DeepLinkTargetRendersInsideUnfoldedCluster, and TestGenerateC2View_DeepCrossLinkTargetChain (C2 call site untouched) all stay green.

**Exclusion (per plan/todo item 4):** the 93.8 Mpt² compactness comparison was NOT re-run — the reporter's model is not in the repo. The fixture-based invariant test (TestC1RootStaysCompactOnDeepCrossFixture, exact hand-derived node set + edge endpoints) is the in-repo proxy: pre-fix root depicted the whole model (8/8 internal units); post-fix it depicts exactly 9 nodes (4 boundary + 4 chain leaves + 1 collapsed container child) across clusters actors⊃identity, yic⊃pipeline⊃(ingest, store).

## Bug 3 — Canonical Merge-Key Reconciliation (todo item 2)

The user reported merging "by shape/color/label/direction after flags". Reconciliation:
- **The builder's merge keys were already pre-flag and stay canonical** (todo item 1 = keep): resolved views use the pair key `path + "->" + link.Peer` (D-01/D-02); expanded mode keys tech+description (COMPAT-02). Both are computed from model data before any flag is consulted; flag-suppressible attributes (color/label/style) deliberately do not belong in the key. Post-merge thickness display unchanged (D-04 + AGG aggregates). D-01/D-02 comment blocks now state the invariant: "flags never change merge outcomes or edge topology, only styling".
- **The second comparison layer was the converter**: `createEdge` built the cgraph edge name from `Source + "_to_" + Target + sanitized(label.Description)`, and `CreateEdgeByName` is find-or-create — so flag-suppressible description text decided drawn-edge identity. Same-description parallel edges collapsed even with no flags (expanded 6→5); under `--no-labels` every label nils and ALL parallel edges collapsed to `src_to_dst`.
- **Fix**: `graph.Edge.Name` — builder assigns `"{source}_to_{target}_{n}"` with a per-(source, target) sequence number from the PRE-dedup walk, sanitized to [A-Za-z0-9_] (`sanitizeEdgeName`, builder mirror of the renderer's sanitizer — threat T-Q1-01). Converter uses it verbatim; hand-built graphs fall back to a uniquified sanitized `src_to_dst` (no label-derived naming anywhere — the plan's grep criterion holds; threat T-Q1-02 closed).
- **Audit (todo item 3, no changes needed)**: validator mirror synthesis (internal/validator/index.go populateIncomingLinks) is pre-flag by construction — Mirror copies duplicate model links before any flag exists and are excluded from pair counting (WR-02), and now also from C1 boundary resolution. View-layer resolution (scope.go ResolvedLinks) computes from model links pre-flag; flags thread only via renderOptsFromView at graph build.
- TestEdgeTopologyFlagInvariant pins the emitted edge-statement multiset + penwidth display identical across no-flags/--no-labels/--no-colors/--no-styles/--plain/--no-labels+--no-colors on C1 (1 edge: pair collapse + mirror dedup) and expanded views (6 edges: every parallel link separate per COMPAT-02, mirror drawn separately — pre-existing v1.7 semantics). TestBuildEdgesPairCollapse, TestBuildEdgesPenwidth*, TestPairAggregation, TestBuildEdgesExpandedExemption stay green.
